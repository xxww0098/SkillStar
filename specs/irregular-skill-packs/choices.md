# 选择清单（最终版）

`specs/irregular-skill-packs` 全部 6 档（00–06）完成后，对照最终代码重新核对过的选择记录。只记录规格没有写死、由实现过程决定的事；不记录门禁结果、测试计数或 e2e 过程证据（那些在提交历史和 CI 里，不在这里）。按确定程度分组，最不确定的排最前面。

## 可能想看一眼的决定

这些是实现者在有真实备选方案的地方做的判断，或者是过程中出现、值得知道的意外情况。都可以推翻；标了改起来大概多大。

1. **物化子路径失败时静默吞错，只在下次重新应用稀疏集时自愈**（`inventory::materialize_dirs`，04 就有的既有设计，06 复用）。
   好处：偶发的网络/git 失败不会让整个安装流程崩溃，下次任何触发稀疏重应用的操作（fetch、reset）都会把漏掉的目录补上。
   代价：用户看到的报错是通用的「没找到 SKILL.md」，不会提示「网络不稳定，请重试」这种更有用的信息——06 实现期间就撞见过一次这样的真实失败（构建机极度资源紧张时，对真实 `pbakaus/impeccable` 仓库安装带子路径的 tree URL，钉住的子路径没物化上）；换一台不那么忙的机器、或者直接用裸 git 命令重放同一套操作，都立刻成功，判断是环境瞬时问题不是逻辑错误，但这类静默失败以后如果频繁出现，报错信息这块值得单独改一次。改动范围：只在 `materialize_dirs` 的错误分支加日志或改错误传播方式，不影响其他逻辑。

2. **插件提示要求「同时」有 `.claude-plugin/*.json` 清单和至少一个 `hooks`/`agents` 目录才显示**（`plugin_manifest::plugin_hint` 的 AND 判定）。
   也可以选「只要声明了插件就提示」（OR 判定）。选 AND 是因为一个只含 skills、没有 hooks/agents 的插件清单没什么好提示用户跳过的——但如果用户觉得「这是插件」本身就值得说一声（不管有没有 hooks/agents），这里要改是一行判定式（`is_plugin && (hooks || agents)` 改成 `is_plugin`）。

3. **H3（04）和 H5（06）两个审查点都是在证据充分、但没等到用户实际点头的情况下自行推进的**——不是流程违规（规格原文写明这两个审查点「不阻塞」，约 5 分钟没回应就按证据决定），只是记录一下：用户如果现在才第一次看这两档的截图/数字，看到的是「已经做了」而不是「请确认」。04 的证据是隔离环境全绿加 4 个夹具级钉住测试加 1 个更新追踪测试；06 的证据见上面第 1 条附带的复现排查。

4. **当时的 devMock 把插件提示演示触发条件写死成「subpath 里含 impeccable 字符串」。** 那个浏览器 mock 已随 React 删除，不要恢复。生产判定仍以扫描结果里的 `plugin` 为准。

5. **`.agent` 与 `.agents` 不再同级**（01 档定的，最终态保留未变）：`.agent` 归入选副本表的「其他」档，不与 `.agents` 并列争抢同一优先级。这是照着规格「全局决定 3」那张表的字面意思做的——表里只列了 `.agents`——仓库作者没有明说这两个目录该不该同等对待，如果以后有仓库同时用 `.agent/` 和 `.agents/` 装不同内容，这条判断可能需要重新讨论。

## 证据支撑、按规格执行

以下都有夹具测试、真实网络探针或规格原文的明确指示支撑，不需要用户复核；列出来是为了这份清单本身能独立说清楚整个功能做了什么。

- **选副本只有一张表**（`pack_layout::choose_copy`），替换掉原来三套互不一致的排名逻辑（inventory 的、discovery 的、harness 回退链各自一套）。默认顺序是根 → `skills/`/`source/skills/` → `.agents/skills/` → manifest 声明的容器 → 其他；点某个 harness 图标时该 harness 的目录优先；技能被钉住时只认钉住的那一个目录。平局一律按路径字典序，不依赖文件系统遍历顺序。
- **技能身份按 frontmatter `name` 判定，不是按目录名**。先按目录 basename 分组，组内内容不同的（tree SHA 不同）批量预取各自的 `SKILL.md` 读 `name` 字段；`name` 相同就是同一个技能的不同改写版本，只保留一份实际物化，其余延迟到需要时才拉取；`name` 读不出来时保守退回旧规则（只延迟字节完全相同的副本），绝不会因为身份判断错误丢掉一个真实存在的技能。
- **物化到磁盘的稀疏集合只增不减**：每次重新计算该拉哪些目录时，已经在磁盘上的技能目录和已安装技能记录的来源目录都会保留，不会被收缩掉——否则已经建好的 Agent 符号链接会变成悬空链接。
- **子路径 tree URL 是硬钉**：装的时候带了子路径的仓库 URL，会把这一份内容写进 lock 并标记「钉住」；钉住之后，无论是点其他 harness 图标还是用不带子路径的普通 URL 重装，都不会再切换到其他副本，只有卸载才能解除钉住。
- **来源信息（仓库地址、ref、子路径、要装的技能名过滤）在一次安装里只解析一次**，贯穿到底传递，不在多个函数里各自重复解析。扫描预览和安装看到的是同一份解析结果，前端也是把整个扫描结果原样传回给安装接口，不用再手工拆分 URL。
- **测试夹具目录全程跳过**：不管是全量扫描还是批量预取身份信息，都会跳过 `tests/`、`test/`、`__tests__/`、`fixtures/` 这类目录，判断只看路径里有没有这些目录名作为祖先，不看子路径本身——所以钉住的子路径即使字面上位于这些目录内部，依然能正常安装（这是唯一的例外）。
- **批量预取而不是逐个懒取**：需要读多份 `SKILL.md` 内容判断身份时，一次性批量取回，比逐个请求快一个数量级（实测约 22 倍）；批量预取失败时不会退化成逐个懒取（那样反而更慢），而是保守退回旧规则。
- **带 ref 的仓库缓存现在也走稀疏检出**，不再是「一旦指定了 ref 就整仓下载」。合并成一条统一的克隆路径：不管有没有 ref，都是 treeless 克隆 + 稀疏模式，有 ref 时额外多做一步「切到那个 ref 对应的提交」，步骤顺序上「切换稀疏模式」必须先于「切换到目标提交」，否则会把整棵树都检出来。失败时的应急下载链路（先试代理直连、再试单次压缩包下载、最后才整仓下载）对带 ref 和不带 ref 的仓库是同一条，没有另写一套。
- **仓库如果是一个 Claude Code 插件（声明了插件清单，且真的有 hooks 或 agents 目录），会提示用户「这些不会被安装」**，引导去用 Claude Code 自带的插件安装方式装完整版本。SkillStar 自己不解析、不安装、不模拟 hooks/agents 的运行时行为——自己实现这套等于把上游仓库自带的安装器重新写一遍。

## 后续如果有人接手

这份规格的六档目标（选副本唯一、按名字判身份、请求级物化、子路径硬钉、GUI 和 CLI 都贯通来源信息并提示插件、ref 缓存也稀疏）全部完成，也全部有测试和真实网络验证支撑（除了「可能想看一眼」第 1 条提到的那次环境性失败，已经用裸 git 复现排除了逻辑问题）。规格本身描述的目标、仓库事实调研、同类工具对比、非目标列表，以及实现过程中每一档更细的技术选择，仍然完整保留在 `README.md` 和 `slices/*.md` 里，这份清单不重复那些内容，只挑出「读代码的人自己未必看得出来、需要额外说明」的判断记下来。
