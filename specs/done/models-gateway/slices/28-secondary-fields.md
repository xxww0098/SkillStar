# 28 — 次要字段

## 契约

Agent 行上的次要字段只显示环回 URL，例如 `127.0.0.1:21847`。不显示厂商主机，不显示密钥。

## 缝

字段由 gateway 的「当前写入 URL」投影而来，前端不拼接厂商端点。

## 人可以运行

保存 Codex 或 OpenCode 之后，该行的次要字段与文件里的 URL 一致，且是环回。

## 视觉

变量只有一个：次要字段的字符串。

裁剪：Agent 名称下方的那一行。

本档不评：行高、图标、选择器是否打开、三栏标题。

screenshot-critique，以及有 `assets/magpie/28-secondary.png` 时的 compare-screenshots。裁剪只盖住这行字。视口两档。preview-shots 约 5 分钟。

验收句：次要字段是环回地址；同一裁剪里没有厂商 URL，也没有密钥。

## 验证

- 投影测试：厂商端点即使存在于 v4 store，次要字段仍是环回
- 界面文本搜索测试用的厂商主机，结果为 0

## 可改

端口与路径之间的呈现，只要主机是 `127.0.0.1`。

## 不可改

不展示厂商 URL、不展示密钥、值来自实际写入。

## 必须保持绿

07 与 26 的测试。

## 会改这一档的反馈

次要字段出现 `api.openai.com` 或其它非环回主机。

## 决定

- 未保存过的 Agent 这一格为空，不预填厂商 URL。
- 显示成 `127.0.0.1:<端口>`，不带协议，也不带路径。端口来自文件里的 `http://127.0.0.1:<端口>`。
- 文件里只有厂商 URL 时这一格仍为空。provider 存储里的端点不参与。
- 页面只画出以 `127.0.0.1:` 加端口的字符串。其它字符串不画。
- Alma 在跑时写的是本地 API，Cindy 只有导入链接。这两行没有可回读的环回文件，格子为空。Hanako 读 catalog 文件；只改了正在跑的 API、文件里还没有环回地址时，格子仍为空。
- 参照作物 `28-secondary.png` 不在仓库里。screenshot-critique 技能不在磁盘上。1440×900 与 1280×800 上，Codex 名称下面是 `127.0.0.1:21847`，其它 Agent 这一格为空。没有 `https://`，也没有厂商主机。五问：这一行是在说该 Agent 指到哪一个环回地址；上一档的掩码还在提供商列；这一屏没有厂商 URL 和密钥；没有参照作物，地址文本就是契约；第一下点的仍是 Agent 行。按此接受。
